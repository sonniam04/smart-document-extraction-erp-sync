# Spec Delta

## Purpose

กำหนดการรับไฟล์เอกสารทางการเงินเข้าสู่ระบบอย่างปลอดภัย — ชนิดไฟล์ที่รองรับ, การคัดกรองไฟล์อันตรายและไฟล์ซ้ำ, การเก็บต้นฉบับ และการแจ้งความคืบหน้าให้ผู้อัปโหลด (BRD FR-01)

## ADDED Requirements

### Requirement: Supported file types and size
ระบบ SHALL รับไฟล์ PDF (หน้าเดียวหรือหลายหน้า), TIFF, JPG และ PNG ขนาดไม่เกิน 20 MB ต่อไฟล์ ระบบ MUST ตรวจชนิดไฟล์จากเนื้อหาจริงของไฟล์ ไม่ใช่จากนามสกุลหรือ header ที่ client ส่งมา

#### Scenario: ไฟล์ที่รองรับ
- **WHEN** ผู้ใช้อัปโหลด PDF ขนาด 3 MB
- **THEN** ระบบรับไฟล์และสร้างเอกสารใหม่ในสถานะ `UPLOADED`

#### Scenario: ไฟล์ใหญ่เกิน
- **WHEN** ผู้ใช้อัปโหลดไฟล์ขนาด 21 MB
- **THEN** ระบบปฏิเสธพร้อมเหตุผล "ไฟล์ใหญ่เกิน 20 MB" และไม่สร้างเอกสาร

#### Scenario: เปลี่ยนนามสกุลหลอก
- **WHEN** ผู้ใช้อัปโหลดไฟล์ปฏิบัติการที่เปลี่ยนชื่อเป็น `.pdf`
- **THEN** ระบบปฏิเสธพร้อมเหตุผล "ชนิดไฟล์ไม่รองรับ"

### Requirement: Malware scanning
ระบบ SHALL สแกนไวรัสทุกไฟล์ก่อนจัดเก็บถาวร ไฟล์ที่ตรวจพบมัลแวร์ MUST ถูกปฏิเสธและไม่ถูกเก็บ หากตัวสแกนไม่พร้อมใช้งาน ระบบ MUST ปฏิเสธการรับไฟล์ (fail closed) แทนการข้ามการสแกน

#### Scenario: ตรวจพบไวรัส
- **WHEN** ผู้ใช้อัปโหลดไฟล์ทดสอบ EICAR
- **THEN** ระบบปฏิเสธพร้อมเหตุผล "ตรวจพบไฟล์อันตราย" และบันทึกเหตุการณ์ลง audit trail

#### Scenario: ตัวสแกนล่ม
- **WHEN** บริการสแกนไวรัสไม่ตอบสนอง
- **THEN** ระบบปฏิเสธการอัปโหลดพร้อมข้อความให้ลองใหม่ภายหลัง และไม่เก็บไฟล์

### Requirement: Duplicate file detection
ระบบ SHALL คำนวณ SHA-256 ของเนื้อหาไฟล์ทุกไฟล์ และ MUST ปฏิเสธไฟล์ที่มี hash ตรงกับเอกสารที่มีอยู่แล้วในระบบ โดยแจ้งเลขอ้างอิงของเอกสารเดิม ยกเว้นเอกสารเดิมอยู่ในสถานะ `FAILED` จากการประมวลผล

#### Scenario: อัปโหลดไฟล์เดิมซ้ำ
- **WHEN** ผู้ใช้อัปโหลดไฟล์ที่เหมือนกับเอกสาร DOC-000123 ทุก byte
- **THEN** ระบบปฏิเสธพร้อมเหตุผล "ไฟล์ซ้ำกับเอกสาร DOC-000123"

#### Scenario: ไฟล์ต่างกันเล็กน้อย
- **WHEN** ผู้ใช้อัปโหลดภาพสแกนใบเดิมที่สแกนใหม่ (byte ต่างกัน)
- **THEN** ระบบรับไฟล์ตามปกติ (การตรวจซ้ำระดับเนื้อหาอยู่ในขั้นดึงข้อมูล ไม่ใช่ขั้นนี้)

### Requirement: Batch upload
ผู้ใช้ SHALL อัปโหลดได้หลายไฟล์ในครั้งเดียว ระบบ MUST ตัดสินผลของแต่ละไฟล์แยกกัน ไฟล์ที่ไม่ผ่านต้องไม่ทำให้ไฟล์อื่นในชุดเดียวกันล้มเหลว

#### Scenario: ชุดที่มีไฟล์เสียปน
- **WHEN** ผู้ใช้อัปโหลด 5 ไฟล์ โดยมี 1 ไฟล์ใหญ่เกิน 20 MB
- **THEN** ระบบรับ 4 ไฟล์ และแสดงผลรายไฟล์ว่าไฟล์ใดถูกปฏิเสธเพราะอะไร

### Requirement: Original file retention
ระบบ SHALL เก็บไฟล์ต้นฉบับแบบเข้ารหัสขณะจัดเก็บ (AES-256) และ MUST ไม่แก้ไขหรือเขียนทับต้นฉบับหลังจัดเก็บแล้ว การเข้าถึงไฟล์ MUST ผ่านการตรวจสิทธิ์และใช้ลิงก์ชั่วคราวที่หมดอายุภายใน 5 นาที

#### Scenario: ดาวน์โหลดต้นฉบับ
- **WHEN** ผู้ใช้ที่มีสิทธิ์ดูเอกสารขอเปิดไฟล์ต้นฉบับ
- **THEN** ระบบให้ลิงก์ที่ใช้ได้ไม่เกิน 5 นาที และ hash ของไฟล์ที่ได้ตรงกับตอนอัปโหลด

#### Scenario: ไม่มีสิทธิ์
- **WHEN** ผู้ใช้ที่มีเพียง role `SYS_ADMIN` ขอไฟล์ต้นฉบับ
- **THEN** ระบบตอบกลับ 403

### Requirement: Processing hand-off
เอกสารที่รับเข้าสำเร็จ SHALL ถูกส่งเข้าคิวประมวลผลแบบ asynchronous โดยการอัปโหลด MUST ตอบกลับผู้ใช้ได้โดยไม่ต้องรอการประมวลผลเสร็จ และ MUST ไม่สูญหายหากบริการคิวหรือ worker รีสตาร์ต

#### Scenario: ตอบกลับทันที
- **WHEN** ผู้ใช้อัปโหลดไฟล์ที่ผ่านการตรวจ
- **THEN** ระบบตอบกลับพร้อมเลขอ้างอิงเอกสารภายใน 5 วินาที (ไม่นับเวลาส่งไฟล์) และเอกสารเข้าคิวรอประมวลผล

#### Scenario: Worker รีสตาร์ตกลางคัน
- **WHEN** worker หยุดทำงานระหว่างที่มีเอกสารอยู่ในคิว
- **THEN** เมื่อ worker กลับมา เอกสารเหล่านั้นถูกประมวลผลต่อโดยไม่ต้องอัปโหลดใหม่

### Requirement: Real-time progress
ผู้อัปโหลดและผู้ใช้ที่เปิดหน้าคิวเอกสาร SHALL เห็นการเปลี่ยนสถานะของเอกสารโดยไม่ต้องรีเฟรชหน้า ภายใน 3 วินาทีหลังสถานะเปลี่ยน

#### Scenario: สถานะเปลี่ยนระหว่างเปิดหน้าอยู่
- **WHEN** เอกสารเปลี่ยนจาก `UPLOADED` เป็น `PROCESSING` ขณะผู้ใช้เปิดหน้าคิว
- **THEN** สถานะบนหน้าจอเปลี่ยนตามภายใน 3 วินาที

#### Scenario: การเชื่อมต่อหลุด
- **WHEN** การเชื่อมต่อ real-time หลุดแล้วกลับมาใหม่
- **THEN** หน้าจอดึงสถานะล่าสุดของทุกเอกสารที่แสดงอยู่ให้ตรงกับ server

### Requirement: Concurrent upload capacity
ระบบ SHALL รองรับการอัปโหลดพร้อมกัน 50 ไฟล์โดยไม่มีไฟล์ใดล้มเหลวเพราะภาระระบบ (BRD NFR Performance)

#### Scenario: อัปโหลดพร้อมกัน 50 ไฟล์
- **WHEN** ผู้ใช้หลายคนอัปโหลดรวม 50 ไฟล์ขนาด 5 MB พร้อมกัน
- **THEN** ทุกไฟล์ได้รับเลขอ้างอิงเอกสารและเข้าคิวสำเร็จ
