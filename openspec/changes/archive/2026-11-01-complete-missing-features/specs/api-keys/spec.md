# Spec Delta

## Purpose

ให้ระบบภายนอก เช่น เครื่องสแกน สคริปต์นำเข้า หรือ ERP เรียก API ของ SDES ได้โดยไม่ใช้บัญชีของคน ด้วย API key ที่ System Admin ออก จำกัดสิทธิ์ เพิกถอนได้ และตรวจสอบย้อนหลังได้ทุกครั้ง

## ADDED Requirements

### Requirement: Issue API key
System Admin SHALL สร้าง API key ได้โดยระบุชื่อ (ไม่ซ้ำกับ key ที่ยังใช้งานได้), ขอบเขตสิทธิ์อย่างน้อยหนึ่งอย่างจาก "อัปโหลดเอกสาร" และ "อ่านสถานะเอกสาร" และอายุ 1–365 วัน (ค่าเริ่มต้น 90 วัน) ค่าของ key MUST แสดงเพียงครั้งเดียวตอนสร้าง role อื่น MUST สร้างหรือดู key ไม่ได้

#### Scenario: สร้าง key สำหรับเครื่องสแกน
- **WHEN** System Admin สร้าง key ชื่อ "เครื่องสแกนชั้น 3" สิทธิ์อัปโหลดเอกสาร อายุ 90 วัน
- **THEN** ระบบแสดงค่า key หนึ่งครั้งพร้อมคำเตือนให้คัดลอกเก็บ และรายการ key แสดงชื่อ ขอบเขต วันหมดอายุ และส่วนต้นของ key โดยไม่มีค่าเต็ม

#### Scenario: ไม่เลือกขอบเขต
- **WHEN** System Admin สร้าง key โดยไม่เลือกขอบเขตสิทธิ์
- **THEN** ระบบปฏิเสธพร้อมแจ้งให้เลือกอย่างน้อยหนึ่งอย่าง

#### Scenario: Clerk เรียก API จัดการ key
- **WHEN** ผู้ใช้ role `AP_CLERK` เรียก API รายการ API key
- **THEN** ระบบตอบกลับ 403

### Requirement: API key storage
ระบบ SHALL เก็บเพียงค่า hash และส่วนต้นของ key ค่าเต็ม MUST ไม่อยู่ในฐานข้อมูล, log, audit หรือคำตอบของ API หลังการสร้าง

#### Scenario: อ่านข้อมูล key จากฐานข้อมูล
- **WHEN** อ่านแถวของ key ตรงจากฐานข้อมูล
- **THEN** ไม่พบค่า key เต็มในรูปข้อความเดิม

### Requirement: Authenticate with API key
ระบบภายนอก SHALL เรียก API ได้ด้วย key ที่ยังไม่หมดอายุและไม่ถูกเพิกถอน และทำได้เฉพาะ endpoint ที่อยู่ในขอบเขตของ key key MUST ใช้ endpoint นอกขอบเขต, endpoint ของผู้ดูแลระบบ หรือการอนุมัติ/แก้ข้อมูลเอกสารไม่ได้ ระบบ MUST บันทึกเวลาใช้งานล่าสุดของ key

#### Scenario: อัปโหลดด้วย key
- **WHEN** เครื่องสแกนอัปโหลดไฟล์ด้วย key ที่มีสิทธิ์อัปโหลด
- **THEN** เอกสารถูกสร้างตามปกติ ผู้อัปโหลดคือ key นั้น และหน้ารายการ key แสดงเวลาใช้ล่าสุด

#### Scenario: ใช้นอกขอบเขต
- **WHEN** key ที่มีเพียงสิทธิ์อ่านสถานะเอกสารพยายามอัปโหลดไฟล์
- **THEN** ระบบตอบกลับ 403

#### Scenario: key หมดอายุ
- **WHEN** ระบบภายนอกเรียก API ด้วย key ที่เลยวันหมดอายุแล้ว
- **THEN** ระบบตอบกลับ 401 โดยไม่บอกว่า key เคยมีอยู่หรือไม่

### Requirement: Revoke API key
System Admin SHALL เพิกถอน key ได้ทุกเมื่อผ่านกล่องยืนยัน และ key ที่ถูกเพิกถอน MUST ใช้ไม่ได้ในคำขอถัดไปทันที

#### Scenario: เพิกถอน key ที่รั่ว
- **WHEN** System Admin เพิกถอน key แล้วระบบภายนอกเรียก API ด้วย key นั้น
- **THEN** ระบบตอบกลับ 401 และรายการ key แสดงสถานะ "เพิกถอนแล้ว" พร้อมผู้เพิกถอนและเวลา

### Requirement: API key audit
การสร้างและเพิกถอน key SHALL มี audit event ระบุผู้ดูแลที่ทำ และการกระทำที่ทำด้วย key MUST ถูกบันทึกใน audit ในชื่อของ key นั้น แยกจากผู้ใช้ที่เป็นคน

#### Scenario: ดูประวัติเอกสารที่อัปโหลดด้วย key
- **WHEN** Finance Exec เปิด audit trail ของเอกสารที่เครื่องสแกนอัปโหลด
- **THEN** ผู้กระทำของ event อัปโหลดแสดงเป็นชื่อ key "เครื่องสแกนชั้น 3"
