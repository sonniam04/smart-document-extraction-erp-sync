# Proposal

## Why

ตอนนี้หลังล็อกอิน ผู้ใช้ถูกส่งไปหน้ารายการเอกสาร (หรือหน้าผู้ใช้สำหรับ System Admin) ทันที ไม่มีที่ใดให้เห็นภาพรวมว่าวันนี้มีงานค้างเท่าไร ระบบทำได้ตามเป้าใน BRD หรือไม่ และมีอะไรผิดปกติที่ต้องรีบจัดการ ข้อมูลเหล่านี้กระจายอยู่ในหน้าคิวเอกสาร หน้ารายงาน หน้าติดตามการส่ง และ System logs

ผู้ใช้ขอให้เพิ่มหน้าภาพรวม (dashboard) ก่อนขึ้น Phase 4 เพื่อให้ระบบครบก่อนการ optimize และ deploy

## What Changes

- **หน้าภาพรวมที่ `/`** แทนการ redirect เดิม และกลายเป็นหน้าแรกหลังล็อกอินของทุก role พร้อมเมนู "ภาพรวม" เป็นรายการแรก
- **เนื้อหาเปลี่ยนตามสิทธิ์ของผู้ใช้** แต่ละส่วนแสดงเฉพาะเมื่อผู้ใช้มีสิทธิ์ดูข้อมูลส่วนนั้นอยู่แล้ว:
  - **งานค้าง** (ผู้ที่ดูเอกสารได้): จำนวนเอกสารรอตรวจ อ่านไม่สำเร็จ กำลังอ่าน รออนุมัติ และส่งไม่สำเร็จ พร้อมอายุของงานที่ค้างนานที่สุด กดแล้วไปที่แท็บนั้นในคิวเอกสาร (หรือหน้ารออนุมัติ)
  - **ปริมาณงาน**: จำนวนที่อัปโหลด ตรวจแล้ว และส่งเข้า ERP สำเร็จในวันนี้ และแนวโน้มรายวัน 14 วันล่าสุด
  - **ตัวชี้วัดตาม BRD** (7 วันล่าสุด): เวลาเฉลี่ยตั้งแต่อัปโหลดจนอ่านเสร็จเทียบเป้า 30 วินาที, สัดส่วนเอกสารที่ไม่ต้องแก้ค่าที่ AI อ่านเทียบเป้า 92%, และสัดส่วนที่ต้องส่งให้หัวหน้าอนุมัติ
  - **การเงินเดือนนี้** (Finance Exec): ยอดซื้อ ภาษีซื้อ และภาษีหัก ณ ที่จ่ายของเดือนปัจจุบันเทียบเดือนก่อน พร้อมลิงก์ไปหน้ารายงาน
  - **สุขภาพระบบ** (System Admin, Finance Exec อ่านอย่างเดียว): งานในคิวอ่านและคิวส่ง, สถานะการเชื่อมต่อ ERP และการส่งอัตโนมัติ, เวลาส่งสำเร็จล่าสุด, จำนวน error ใน 24 ชั่วโมง (เฉพาะผู้ที่ดู system logs ได้) และ API key ที่จะหมดอายุใน 14 วัน (เฉพาะผู้ที่จัดการ key ได้)
- ข้อมูลอัปเดตเองทุก 30 วินาทีขณะเปิดหน้า
- **สิทธิ์:** เพิ่มสิทธิ์ `dashboard.view` ให้ทุก role ของคน (บัญชีของ API key ไม่มีสิทธิ์นี้)
- **คิวเอกสาร:** รองรับการเปิดแท็บที่ระบุผ่าน URL (`/documents?tab=...`) เพื่อให้ลิงก์จากหน้าภาพรวมพาไปถูกที่

## Capabilities

### New Capabilities
- `overview-dashboard`: หน้าภาพรวมหลังล็อกอิน ประกอบด้วยงานค้าง ปริมาณงาน ตัวชี้วัดตาม BRD การเงินเดือนนี้ และสุขภาพระบบ โดยแสดงแต่ละส่วนตามสิทธิ์ของผู้ใช้

### Modified Capabilities
- `user-access`: permission matrix เพิ่ม `dashboard.view` ให้ทุก role

## Impact

- **Service (`sdes-service`):** endpoint ใหม่ `GET /dashboard` (สิทธิ์ `dashboard.view`) ที่ประกอบผลตามสิทธิ์ของผู้เรียก, ย้ายการคำนวณตัวชี้วัดกระบวนการของ `/reports/summary` ไปเป็นฟังก์ชันกลางเพื่อใช้ร่วมกัน, permission ใหม่ใน `packages/core` (ต้อง `pnpm sync:core` ไปเว็บ)
- **Web (`sdes-web`):** หน้า `/` ใหม่, `homeFor()` คืน `/` ทุก role, เมนู "ภาพรวม" ใน `lib/roles.ts`, คิวเอกสารอ่าน `?tab=`
- **ไม่กระทบ:** API และหน้าจอเดิมทั้งหมด; หน้ารายงานและหน้าติดตามการส่งยังเป็นที่ดูรายละเอียดเหมือนเดิม
- **นอกขอบเขต:** การปรับแต่งหน้า dashboard เอง (ย้าย/ซ่อนการ์ด), การแจ้งเตือนทางอีเมลหรือ push, ข้อมูลแบบ real-time ผ่าน WebSocket, library กราฟใหม่
- **Branch:** แตกต่อจาก `feat/complete-missing-features` (Service/Web) และ `docs/complete-missing-features` (repo หลัก) จนกว่า PR ก่อนหน้าจะ merge
- **สมมติฐานที่ต้องรีวิว:** BRD ไม่ได้กำหนดหน้า dashboard ไว้ ส่วนต่าง ๆ และตัวชี้วัดข้างต้นจึงเลือกจากเป้าหมายใน BRD (เวลา < 30 วินาที, ความแม่นยำ > 92%, เกณฑ์ความมั่นใจ 85%) และข้อมูลที่ระบบมีอยู่แล้ว ปรับได้ตอนรีวิว
