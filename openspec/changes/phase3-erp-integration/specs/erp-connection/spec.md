# Spec Delta

## Purpose

ให้ System Admin ตั้งค่า ทดสอบ และเปิด/ปิดการเชื่อมต่อกับ ERP ได้เองอย่างปลอดภัย โดย secret ของการเชื่อมต่อไม่รั่วไหลและทุกการแก้ไขตรวจสอบย้อนหลังได้

## ADDED Requirements

### Requirement: Connection settings
System Admin SHALL ตั้งค่าการเชื่อมต่อ ERP ได้: ชนิด adapter (`odoo` หรือ `webhook`), URL ปลายทาง, ฐานข้อมูล (Odoo), API key หรือ webhook secret, journal ซื้อ, รหัสภาษีซื้อ 7% และบัญชีค่าใช้จ่ายเริ่มต้น (Odoo) ค่าที่ไม่ครบหรือรูปแบบผิด MUST ถูกปฏิเสธพร้อมบอกช่องที่ผิด role อื่นดูหรือแก้ไม่ได้

#### Scenario: ตั้งค่า Odoo
- **WHEN** System Admin บันทึก URL, ฐานข้อมูล, API key, journal, รหัสภาษี และบัญชีค่าใช้จ่ายครบ
- **THEN** การตั้งค่าถูกบันทึก และหน้าตั้งค่าแสดงค่าทั้งหมดยกเว้น API key

#### Scenario: URL ไม่ถูกต้อง
- **WHEN** System Admin กรอก URL ที่ไม่ใช่ http(s)
- **THEN** ระบบปฏิเสธพร้อมข้อความที่ชี้ช่อง URL

#### Scenario: Finance Exec เปิดหน้าตั้งค่า
- **WHEN** ผู้ใช้ที่มีเพียง role `FINANCE_EXEC` เรียก API อ่านการตั้งค่า ERP
- **THEN** ระบบตอบกลับ 403

### Requirement: Secret protection
API key และ webhook secret SHALL ถูกเก็บแบบเข้ารหัส (AES-256-GCM) ด้วยกุญแจที่อยู่นอกฐานข้อมูล และ MUST ไม่ถูกส่งกลับในคำตอบของ API, ไม่ปรากฏใน log และไม่ปรากฏใน audit (audit บันทึกเพียงว่ามีการเปลี่ยน) การบันทึกโดยเว้นช่อง secret ว่าง MUST คงค่าเดิมไว้

#### Scenario: อ่านการตั้งค่า
- **WHEN** System Admin เปิดหน้าตั้งค่าหลังบันทึก API key แล้ว
- **THEN** คำตอบของ API มีเพียงสถานะว่าตั้ง key แล้ว ไม่มีค่า key

#### Scenario: เปลี่ยน API key
- **WHEN** System Admin เปลี่ยน API key
- **THEN** มี audit event "เปลี่ยน secret ของการเชื่อมต่อ ERP" โดยไม่มีค่าเก่าหรือใหม่ใน event

#### Scenario: ข้อมูลในฐานข้อมูล
- **WHEN** อ่านแถวการตั้งค่าตรงจากฐานข้อมูล
- **THEN** ไม่พบ API key ในรูปข้อความเดิม

### Requirement: Connection test
System Admin SHALL ทดสอบการเชื่อมต่อได้จากหน้าตั้งค่า การทดสอบ MUST ตรวจว่าเข้าถึงปลายทางได้, ยืนยันตัวตนผ่าน, และ (สำหรับ Odoo) journal รหัสภาษี และบัญชีที่ตั้งไว้มีอยู่จริง แล้วแสดงผลแยกรายข้อ การทดสอบ MUST ไม่สร้างข้อมูลใด ๆ ใน ERP

#### Scenario: API key ผิด
- **WHEN** System Admin ทดสอบด้วย API key ที่ Odoo ไม่รับ
- **THEN** ผลทดสอบแสดงว่ายืนยันตัวตนไม่ผ่าน และข้อที่เหลือไม่ถูกตรวจ

#### Scenario: รหัสภาษีไม่มีใน Odoo
- **WHEN** รหัสภาษีซื้อที่ตั้งไว้ไม่มีใน Odoo
- **THEN** ผลทดสอบแสดงว่าข้อรหัสภาษีไม่ผ่าน ส่วนข้ออื่นผ่าน

### Requirement: Automatic sync switch
การส่งอัตโนมัติ SHALL ปิดอยู่จนกว่าการทดสอบการเชื่อมต่อด้วยการตั้งค่าปัจจุบันจะผ่าน System Admin เปิดหรือปิดได้ทุกเมื่อ และการแก้การตั้งค่าการเชื่อมต่อ MUST ปิดการส่งอัตโนมัติจนกว่าจะทดสอบผ่านอีกครั้ง

#### Scenario: เปิดโดยยังไม่ทดสอบ
- **WHEN** System Admin เปิดการส่งอัตโนมัติก่อนทดสอบการเชื่อมต่อผ่าน
- **THEN** ระบบปฏิเสธพร้อมแจ้งให้ทดสอบก่อน

#### Scenario: แก้ URL หลังเปิดใช้
- **WHEN** System Admin แก้ URL ของ Odoo ขณะการส่งอัตโนมัติเปิดอยู่
- **THEN** การส่งอัตโนมัติถูกปิด และเอกสารที่พร้อมส่งรออยู่จนกว่าจะทดสอบผ่านและเปิดอีกครั้ง

### Requirement: Settings audit
ทุกการแก้การตั้งค่า, การทดสอบ และการเปิด/ปิดการส่งอัตโนมัติ SHALL มี audit event พร้อมผู้กระทำและค่าก่อน/หลัง (ยกเว้น secret)

#### Scenario: เปิดการส่งอัตโนมัติ
- **WHEN** System Admin เปิดการส่งอัตโนมัติ
- **THEN** มี audit event ระบุผู้เปิด เวลา และค่าก่อน "ปิด" หลัง "เปิด"
