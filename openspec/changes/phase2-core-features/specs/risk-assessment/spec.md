# Spec Delta

## Purpose

ตัดสินว่าเอกสารที่ Clerk ยืนยันแล้วต้องให้ AP Lead อนุมัติก่อนหรือส่งต่อได้เลย ตามเกณฑ์ที่ตั้งค่าได้ เพื่อไม่ให้เคสเสี่ยงถูกส่งเข้า ERP อัตโนมัติ (BRD ข้อ 6 Fallback Strategy)

## ADDED Requirements

### Requirement: Risk rules
เมื่อเอกสารเปลี่ยนเป็น `VERIFIED` ระบบ SHALL ประเมินความเสี่ยงจากกฎต่อไปนี้: ความมั่นใจรวมต่ำกว่าเกณฑ์ (ค่าเริ่มต้น 0.85), ยอดรวมสูงกว่าเกณฑ์ยอดสูง (ถ้าตั้งไว้), ผู้ขายยังไม่เคยมีเอกสารที่อนุมัติหรือผ่านมาก่อน, มีการแก้ยอดเงินหลังการอ่าน และมีผลตรวจระดับ `WARNING` ค้างอยู่

#### Scenario: ความมั่นใจต่ำ
- **WHEN** เอกสารความมั่นใจรวม 0.80 ถูกยืนยัน
- **THEN** ผลประเมินมีเหตุผล "ความมั่นใจของ AI ต่ำกว่า 85%"

#### Scenario: แก้ยอดเงิน
- **WHEN** Clerk แก้ยอดรวมก่อนยืนยัน
- **THEN** ผลประเมินมีเหตุผล "มีการแก้ยอดเงินหลังการอ่าน" พร้อมชื่อ field ที่ถูกแก้

#### Scenario: ยังไม่ได้ตั้งเกณฑ์ยอดสูง
- **WHEN** เกณฑ์ยอดสูงยังไม่ถูกตั้งค่า
- **THEN** กฎยอดสูงไม่ถูกใช้ และกฎอื่นยังประเมินตามปกติ

### Requirement: Routing after verification
เอกสารที่มีเหตุผลความเสี่ยงอย่างน้อยหนึ่งข้อ SHALL เปลี่ยนเป็น `PENDING_APPROVAL` โดยระบบ ส่วนเอกสารที่ไม่มีความเสี่ยง SHALL คงอยู่ที่ `VERIFIED` เพื่อรอการส่งเข้า ERP เอกสารที่มีความเสี่ยง MUST ไม่ถูกส่งเข้า ERP โดยไม่ผ่านการอนุมัติ

#### Scenario: เคสเสี่ยงเข้าคิว
- **WHEN** เอกสารที่มีผู้ขายใหม่ถูกยืนยัน
- **THEN** เอกสารเป็น `PENDING_APPROVAL` และปรากฏในคิวรออนุมัติของ AP Lead

#### Scenario: เคสไม่เสี่ยง
- **WHEN** เอกสารความมั่นใจ 0.97 จากผู้ขายเดิม ไม่มีการแก้ยอดและไม่มี `WARNING` ถูกยืนยัน
- **THEN** เอกสารคงอยู่ที่ `VERIFIED` และไม่อยู่ในคิวรออนุมัติ

### Requirement: Recorded risk reasons
ผลประเมินความเสี่ยง SHALL ถูกเก็บกับเอกสาร (รหัสกฎ, ข้อความ, ค่าที่ทำให้เข้าเกณฑ์ และค่าเกณฑ์ ณ เวลาประเมิน) และ MUST ถูกบันทึกใน audit trail การแก้เกณฑ์ภายหลัง MUST ไม่เปลี่ยนผลประเมินที่เก็บไว้แล้ว

#### Scenario: ดูเหตุผลย้อนหลัง
- **WHEN** Admin เปลี่ยนเกณฑ์ความมั่นใจเป็น 0.90 หลังเอกสารถูกประเมินที่เกณฑ์ 0.85
- **THEN** เอกสารเดิมยังแสดงว่าถูกประเมินที่เกณฑ์ 0.85

### Requirement: Configurable thresholds
System Admin SHALL ดูและแก้เกณฑ์ความมั่นใจ, เกณฑ์ยอดสูง และ Tax ID กับชื่อของบริษัท (ใช้ตรวจผู้ซื้อ) ได้จากหน้าตั้งค่า ค่าที่ไม่ถูกต้อง MUST ถูกปฏิเสธ และทุกการแก้ MUST มี audit ค่าก่อน/หลัง role อื่นแก้ไม่ได้

#### Scenario: ตั้งเกณฑ์ยอดสูง
- **WHEN** System Admin ตั้งเกณฑ์ยอดสูงเป็น 500,000.00
- **THEN** เอกสารที่ยืนยันหลังจากนั้นและมียอดรวมเกิน 500,000.00 มีเหตุผล "ยอดสูงกว่าเกณฑ์"

#### Scenario: เกณฑ์ความมั่นใจไม่ถูกต้อง
- **WHEN** System Admin ตั้งเกณฑ์ความมั่นใจเป็น 1.5
- **THEN** ระบบปฏิเสธพร้อมแจ้งว่าต้องอยู่ระหว่าง 0 ถึง 1

#### Scenario: Clerk พยายามแก้เกณฑ์
- **WHEN** ผู้ใช้ role `AP_CLERK` ส่งคำขอแก้เกณฑ์
- **THEN** ระบบตอบกลับ 403
