# vendor-directory Specification

## Purpose

ให้ฝ่ายบัญชีเห็นผู้ขายทุกรายที่ระบบรู้จักจากเอกสาร พร้อมประวัติเอกสาร ยอดรวม และสถานะที่มีผลต่อการตรวจความเสี่ยงและการส่ง ERP เพื่อใช้ตรวจสอบก่อนยืนยันหรืออนุมัติ

## Requirements

### Requirement: Vendor list
AP Clerk และ AP Lead SHALL ดูรายการผู้ขายทุกรายที่มีในระบบ แต่ละรายแสดงชื่อ, Tax ID, สาขา, จำนวนเอกสาร, ยอดรวมของเอกสารที่ยืนยันแล้วขึ้นไป (ไม่นับที่ถูกปฏิเสธ), วันที่ของเอกสารล่าสุด, รหัสคู่ค้าใน ERP (ถ้ามี) และป้าย "ผู้ขายรายใหม่" ตามเงื่อนไขเดียวกับที่ระบบใช้ตั้งเหตุผลความเสี่ยง "ผู้ขายรายใหม่" (ยังไม่มีเอกสารที่ยืนยันผ่านโดยไม่ต้องอนุมัติ หรืออนุมัติแล้ว) รายการ MUST ค้นด้วยชื่อหรือ Tax ID ได้และแบ่งหน้า

#### Scenario: ค้นด้วย Tax ID
- **WHEN** Clerk พิมพ์ Tax ID 13 หลักของผู้ขายในช่องค้นหา
- **THEN** รายการแสดงผู้ขายรายนั้นทุกสาขา

#### Scenario: ผู้ขายรายใหม่
- **WHEN** ผู้ขายมีเอกสารที่รออนุมัติเพียงฉบับเดียว
- **THEN** รายการแสดงป้าย "ผู้ขายรายใหม่" ที่ผู้ขายรายนั้น

### Requirement: Vendor detail
ผู้ใช้ที่ดูรายการผู้ขายได้ SHALL เปิดรายละเอียดของผู้ขายแต่ละราย ซึ่งแสดงข้อมูลเดียวกับรายการ และรายการเอกสารของผู้ขายนั้นเรียงจากใหม่ไปเก่าพร้อมสถานะและลิงก์ไปหน้าเอกสาร ข้อมูลผู้ขาย MUST แก้ไขจากหน้านี้ไม่ได้

#### Scenario: ดูเอกสารของผู้ขาย
- **WHEN** AP Lead เปิดรายละเอียดผู้ขายที่มีเอกสาร 3 ฉบับ
- **THEN** เห็นเอกสารทั้ง 3 ฉบับพร้อมเลขเอกสาร เลขใบกำกับ วันที่ ยอดรวม และสถานะ

### Requirement: Vendor directory access
ทะเบียนผู้ขาย SHALL เข้าถึงได้เฉพาะ `AP_CLERK` และ `AP_LEAD` role อื่น MUST ไม่เห็นเมนูและได้ 403 จาก API

#### Scenario: System Admin เรียก API ผู้ขาย
- **WHEN** ผู้ใช้ที่มีเพียง role `SYS_ADMIN` เรียก API รายการผู้ขาย
- **THEN** ระบบตอบกลับ 403
