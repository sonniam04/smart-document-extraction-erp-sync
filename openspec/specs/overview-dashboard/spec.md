# overview-dashboard Specification

## Purpose

ให้ผู้ใช้ทุก role เห็นภาพรวมของงานค้าง ปริมาณงาน ตัวชี้วัดตามเป้าหมายใน BRD การเงิน และสุขภาพของระบบได้ในหน้าเดียวทันทีหลังล็อกอิน โดยเห็นเฉพาะข้อมูลที่ตนมีสิทธิ์ดูอยู่แล้ว

## Requirements

### Requirement: Dashboard as home page
หน้าภาพรวม SHALL เป็นหน้าแรกของระบบสำหรับทุก role หลังล็อกอินและหลังเปลี่ยนรหัสผ่านครั้งแรก เว้นแต่ผู้ใช้ถูกส่งมาล็อกอินจากลิงก์ของหน้าอื่น และ SHALL มีเมนู "ภาพรวม" เป็นรายการแรกของทุก role

#### Scenario: ล็อกอินตามปกติ
- **WHEN** System Admin ล็อกอินสำเร็จโดยไม่ได้มาจากลิงก์ของหน้าอื่น
- **THEN** ระบบเปิดหน้าภาพรวม

#### Scenario: ล็อกอินจากลิงก์เอกสาร
- **WHEN** AP Clerk เปิดลิงก์เอกสารขณะยังไม่ได้ล็อกอิน แล้วล็อกอินสำเร็จ
- **THEN** ระบบเปิดเอกสารนั้น ไม่ใช่หน้าภาพรวม

### Requirement: Sections follow existing permissions
หน้าภาพรวมและข้อมูลของหน้านี้ SHALL แสดงแต่ละส่วนเฉพาะเมื่อผู้ใช้มีสิทธิ์ดูข้อมูลชนิดนั้นในระบบอยู่แล้ว: งานค้าง ปริมาณงาน และตัวชี้วัดตาม BRD ต้องมีสิทธิ์ดูเอกสาร; การเงินต้องมีสิทธิ์ดูรายงาน; สุขภาพระบบต้องมีสิทธิ์ดูการติดตามคิว; จำนวน error ต้องมีสิทธิ์ดู system logs; API key ที่ใกล้หมดอายุต้องมีสิทธิ์จัดการ API key ข้อมูลของส่วนที่ไม่มีสิทธิ์ MUST ไม่ถูกส่งจาก server เลย

#### Scenario: Clerk เปิดหน้าภาพรวม
- **WHEN** ผู้ใช้ที่มีเพียง role `AP_CLERK` เรียกข้อมูลหน้าภาพรวม
- **THEN** ผลลัพธ์มีงานค้าง ปริมาณงาน และตัวชี้วัด แต่ไม่มีข้อมูลการเงินและสุขภาพระบบ

#### Scenario: Admin เปิดหน้าภาพรวม
- **WHEN** ผู้ใช้ที่มีเพียง role `SYS_ADMIN` เรียกข้อมูลหน้าภาพรวม
- **THEN** ผลลัพธ์มีเฉพาะสุขภาพระบบ จำนวน error และ API key ที่ใกล้หมดอายุ ไม่มีจำนวนหรือข้อมูลเอกสารรายฉบับ

#### Scenario: ผู้ใช้หลาย role
- **WHEN** ผู้ใช้ที่มี role `AP_LEAD` และ `FINANCE_EXEC` เปิดหน้าภาพรวม
- **THEN** เห็นทั้งงานค้าง ตัวชี้วัด การเงิน และสุขภาพระบบ

#### Scenario: API key เรียกข้อมูลหน้าภาพรวม
- **WHEN** ระบบภายนอกเรียกข้อมูลหน้าภาพรวมด้วย API key
- **THEN** ระบบตอบกลับ 403

### Requirement: Work backlog
ส่วนงานค้าง SHALL แสดงจำนวนเอกสารในสถานะรอตรวจ (`EXTRACTED`), อ่านไม่สำเร็จ (`FAILED`), กำลังอ่าน (`UPLOADED` และ `PROCESSING`), รออนุมัติ (`PENDING_APPROVAL`) และส่งไม่สำเร็จ (`SYNC_FAILED`) พร้อมเวลาที่เอกสารฉบับเก่าที่สุดของแต่ละกลุ่มรออยู่ จำนวนแต่ละกลุ่ม SHALL เป็นลิงก์ไปยังแท็บที่ตรงกันในคิวเอกสาร หรือหน้ารออนุมัติสำหรับผู้ที่อนุมัติได้

#### Scenario: เอกสารรอตรวจ
- **WHEN** มีเอกสาร `EXTRACTED` 4 ฉบับ ฉบับเก่าที่สุดอ่านเสร็จเมื่อ 3 ชั่วโมงก่อน และ AP Clerk เปิดหน้าภาพรวม
- **THEN** ส่วนงานค้างแสดง "รอตรวจ 4" และ "เก่าสุด 3 ชั่วโมง"

#### Scenario: กดไปที่งานค้าง
- **WHEN** AP Clerk กดจำนวนเอกสารรอตรวจ
- **THEN** ระบบเปิดคิวเอกสารที่แท็บรอตรวจ

#### Scenario: Lead กดงานรออนุมัติ
- **WHEN** AP Lead กดจำนวนเอกสารรออนุมัติ
- **THEN** ระบบเปิดหน้ารออนุมัติ

### Requirement: Throughput
ส่วนปริมาณงาน SHALL แสดงจำนวนเอกสารที่อัปโหลด ตรวจแล้ว (เข้า `VERIFIED` ครั้งแรก) และส่งเข้า ERP สำเร็จ (เข้า `SYNCED` ครั้งแรก) ของวันนี้ และแนวโน้มรายวันของตัวเลขทั้งสามย้อนหลัง 14 วันรวมวันนี้ วันที่นับตามเวลาประเทศไทย และวันที่ไม่มีเอกสาร MUST แสดงเป็น 0 ไม่ถูกข้าม

#### Scenario: วันที่ไม่มีงาน
- **WHEN** ไม่มีเอกสารใดอัปโหลดเมื่อวานซืน
- **THEN** แนวโน้มยังมีวันนั้นด้วยค่า 0

#### Scenario: ข้ามเที่ยงคืน
- **WHEN** เอกสารอัปโหลดเวลา 00:30 น. ตามเวลาประเทศไทย (17:30 UTC ของวันก่อน)
- **THEN** เอกสารนั้นนับเป็นของวันนี้ตามเวลาประเทศไทย

### Requirement: BRD indicators
ส่วนตัวชี้วัด SHALL แสดงค่าของเอกสารที่อัปโหลดใน 7 วันล่าสุด: เวลาเฉลี่ยตั้งแต่อัปโหลดจนอ่านเสร็จเทียบเป้า 30 วินาที, สัดส่วนเอกสารที่ยืนยันแล้วโดยไม่มีการแก้ค่าที่ AI อ่านเทียบเป้า 92%, และสัดส่วนเอกสารที่ยืนยันแล้วที่ต้องส่งให้หัวหน้าอนุมัติ ค่าที่ไม่ถึงเป้า SHALL แสดงเป็นสถานะไม่ผ่านพร้อมตัวเลขเป้า และค่าที่ยังคำนวณไม่ได้ (ไม่มีเอกสาร) MUST แสดงว่า "ยังไม่มีข้อมูล" ไม่ใช่ 0

#### Scenario: เวลาอ่านเกินเป้า
- **WHEN** เวลาเฉลี่ยจากอัปโหลดถึงอ่านเสร็จใน 7 วันล่าสุดเท่ากับ 41 วินาที
- **THEN** ตัวชี้วัดแสดง 41 วินาทีในสถานะไม่ผ่าน พร้อมเป้า "< 30 วินาที"

#### Scenario: ยังไม่มีเอกสารยืนยัน
- **WHEN** ใน 7 วันล่าสุดยังไม่มีเอกสารที่ยืนยันแล้ว
- **THEN** สัดส่วนที่ไม่ต้องแก้ค่าแสดงว่า "ยังไม่มีข้อมูล"

### Requirement: Finance snapshot
ส่วนการเงิน SHALL แสดงยอดซื้อก่อนภาษี ภาษีซื้อ ภาษีหัก ณ ที่จ่าย และยอดรวมของเดือนปัจจุบันตามวันที่ในเอกสาร โดยนับชุดเอกสารเดียวกับหน้ารายงาน พร้อมผลต่างเป็นเปอร์เซ็นต์เทียบเดือนก่อนทั้งเดือน และลิงก์ไปหน้ารายงาน ยอดเงิน MUST ตรงกับหน้ารายงานของเดือนเดียวกันทุกสตางค์

#### Scenario: ยอดตรงกับหน้ารายงาน
- **WHEN** Finance Exec เปิดหน้าภาพรวมและหน้ารายงานของเดือนปัจจุบัน
- **THEN** ยอดรวมทั้งสองหน้าเท่ากัน

#### Scenario: เดือนก่อนไม่มียอด
- **WHEN** เดือนก่อนไม่มีเอกสารที่นับได้
- **THEN** ไม่แสดงเปอร์เซ็นต์ผลต่าง และไม่เกิดการหารด้วยศูนย์

### Requirement: System health
ส่วนสุขภาพระบบ SHALL แสดงจำนวนงานที่ค้างในคิวอ่านและคิวส่ง จำนวนเอกสาร `SYNC_FAILED` สถานะการเชื่อมต่อ ERP และการส่งอัตโนมัติ และเวลาส่งสำเร็จล่าสุด สำหรับผู้ที่ดู system logs ได้ SHALL แสดงจำนวน log ระดับ error ใน 24 ชั่วโมงล่าสุดพร้อมลิงก์ไปหน้า System logs และสำหรับผู้ที่จัดการ API key ได้ SHALL แสดงรายชื่อ key ที่ยังใช้งานได้และจะหมดอายุภายใน 14 วัน

#### Scenario: มี error ใน 24 ชั่วโมง
- **WHEN** มี log ระดับ error 3 รายการในชั่วโมงที่ผ่านมา และ System Admin เปิดหน้าภาพรวม
- **THEN** ส่วนสุขภาพระบบแสดง error 3 รายการพร้อมลิงก์ไปหน้า System logs ที่กรองระดับ error

#### Scenario: Finance Exec ดูสุขภาพระบบ
- **WHEN** Finance Exec เปิดหน้าภาพรวม
- **THEN** เห็นคิว การส่งที่ล้มเหลว และสถานะ ERP แต่ไม่เห็นจำนวน error และ API key

#### Scenario: Key ใกล้หมดอายุ
- **WHEN** มี API key ที่ยังไม่ถูกเพิกถอนและหมดอายุในอีก 5 วัน
- **THEN** System Admin เห็นชื่อ key และวันหมดอายุในส่วนสุขภาพระบบ

### Requirement: Freshness and performance
ข้อมูลหน้าภาพรวม SHALL อัปเดตเองอย่างน้อยทุก 30 วินาทีขณะเปิดหน้าอยู่ และแสดงเวลาที่ข้อมูลถูกดึงล่าสุด ข้อมูลทั้งหน้า MUST ตอบกลับภายใน 1 วินาทีที่ปริมาณเอกสาร 12 เดือนตามปริมาณใน BRD (3,500 ฉบับต่อเดือน) ถ้าการดึงข้อมูลรอบใดล้มเหลว หน้าจอ SHALL คงข้อมูลเดิมไว้และแสดงว่าข้อมูลอาจไม่เป็นปัจจุบัน

#### Scenario: อัปเดตอัตโนมัติ
- **WHEN** หน้าภาพรวมเปิดค้างไว้ และมีเอกสารใหม่อ่านเสร็จ
- **THEN** จำนวนรอตรวจเพิ่มขึ้นภายใน 30 วินาทีโดยผู้ใช้ไม่ต้องรีเฟรช

#### Scenario: ดึงข้อมูลไม่สำเร็จ
- **WHEN** API ไม่ตอบในรอบอัปเดตหนึ่ง
- **THEN** หน้าจอยังแสดงตัวเลขเดิมพร้อมข้อความว่าข้อมูลอาจไม่เป็นปัจจุบัน
