# operations-monitoring Specification

## Purpose

ให้ System Admin (บทบาท IT & System Auditor ใน BRD) เห็นภาพรวมของคิวงานและการส่งเข้า ERP และจัดการเอกสารที่ส่งไม่สำเร็จได้จากที่เดียว

## Requirements

### Requirement: Queue overview
หน้าติดตาม SHALL แสดงจำนวนเอกสารในแต่ละสถานะ, จำนวนงานอ่านและงานส่งที่ค้างในคิว, เวลาที่ส่งสำเร็จล่าสุด และสถานะการส่งอัตโนมัติ (เปิด/ปิด) ข้อมูล MUST เป็นปัจจุบันไม่เกิน 30 วินาที

#### Scenario: เปิดหน้าติดตาม
- **WHEN** System Admin เปิดหน้าติดตามขณะมีเอกสาร `SYNC_FAILED` 2 ฉบับและ `SYNCING` 1 ฉบับ
- **THEN** หน้าจอแสดงตัวเลข 2 และ 1 ในสถานะนั้น พร้อมสถานะการส่งอัตโนมัติ

### Requirement: Failed sync list
หน้าติดตาม SHALL แสดงรายการเอกสาร `SYNC_FAILED` เรียงจากเก่าไปใหม่ พร้อมเลขเอกสาร ผู้ขาย ยอดรวม จำนวนครั้งที่ส่ง และเหตุผลล่าสุด และเลือกหลายรายการเพื่อส่งใหม่พร้อมกันได้

#### Scenario: ส่งใหม่หลายฉบับ
- **WHEN** System Admin เลือก 3 รายการในคิวที่ล้มเหลวแล้วกดส่งใหม่และยืนยัน
- **THEN** ทั้ง 3 รายการเปลี่ยนเป็น `SYNCING` และหายจากรายการที่ล้มเหลว

### Requirement: Monitoring access
หน้าติดตามและข้อมูลของหน้านี้ SHALL เข้าถึงได้เฉพาะ `SYS_ADMIN` และ `FINANCE_EXEC` (อ่านอย่างเดียว ไม่มีปุ่มส่งใหม่) role อื่น MUST ไม่เห็นเมนูและได้ 403 จาก API

#### Scenario: Finance Exec เปิดหน้าติดตาม
- **WHEN** Finance Exec เปิดหน้าติดตาม
- **THEN** เห็นตัวเลขและรายการที่ล้มเหลว แต่ไม่มีปุ่มส่งใหม่

#### Scenario: Clerk เรียก API ติดตาม
- **WHEN** ผู้ใช้ที่มีเพียง role `AP_CLERK` เรียก API ภาพรวมคิว
- **THEN** ระบบตอบกลับ 403
